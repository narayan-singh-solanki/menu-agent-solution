Problem

Mobile, web and kiosk each fetch a raw catalog and apply schedule, stock, price and tax rules themselves, and the rules have drifted. Put them behind one menu agent, so the same call can run in the app today and on a server later without changing the UI.

Use only the attached fixtures/. No live vendor and no third-party mock service.

Build

  1. resolve(ctx) → { catalog, visible, prices, oos }

    ctx: store_id, now, timezone, optional preorder_slot. If a preorder slot is set, judge the schedule at the slot, not at now.

    • catalog: categories, items and modifiers by id
    • visible: delivery and collection trees; out-of-stock and off-schedule items excluded
    • prices[order_type][item_id] = { gross, tax }, integer cents, visible items only
    • oos: ids that cannot be sold
  2. Tax. Use the rate and the inclusive/exclusive flag from store.json, and each item's tax_class. gross is what the guest pays and tax is the part of it that is tax. Round tax to the nearest cent per item, half up.
  3. Modes, chosen by the menu_agent_mode flag:
    FlagSchedule, stockPrice, tax
    localclientclient
    hybridserverclient
    remoteserverserver
    The server can be your own local process or an in-process stub with fail and delay switches. Any server call has a 3s total budget. On failure or timeout, run local on the last cached catalog, recomputed for the current time. Never return an empty menu because the network failed. With no cache at all, show an error state. Changing the flag must not need a code change.
  4. Search, theme and scrolling stay in the client. They are not agent work.
  5. Inspector UI. Pick mode, order type and time (including a preorder slot). List the visible items with price and tax shown as money, not cents. Show the mode used and whether this result was a fallback. Include a switch that makes the server fail. Put mode and order type in the query string (deep-link params in Expo). It must work at 390px wide with no horizontal scroll. Web or Expo (React Native) are both fine. If Expo, add 2–3 Maestro flows: server failing still shows a menu marked as fallback, a preorder slot changes what's visible, and switching mode updates the result.
  6. Mapping table (fixture field → your field) and a conflicts log: a keep, reject or rewrite verdict on every note below, each with a pointer to a fixture.
  7. Tests: schedule in the store's timezone, preorder slot, out of stock, delivery vs collection price, tax (inclusive, exempt, rounding), 3s fallback, cache recompute.

Working notes (unverified)

  1. If the dump already has visible, skip the schedule check.
  2. Put text search in the agent so every surface matches.
  3. In hybrid, the server prices and the client filters, because pricing is the expensive part.
  4. If the server fails, return an empty menu so we never sell stale stock.
  5. Retry the server 3 times, 3s each, before falling back.
  6. available: true is enough to show an item.
  7. Dump prices are dollars; multiply by 100.
  8. Store time is UTC; ignore the timezone.
  9. Delivery and collection share one price.
  10. Dump prices exclude tax; add GST on top.
  11. Every item takes the store tax rate.
  12. Truncate tax to whole cents.
  13. For preorders, check the schedule at now.
